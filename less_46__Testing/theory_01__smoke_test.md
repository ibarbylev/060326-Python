# Smoke Test 

## 1. Smoke Test

**Smoke test** — быстрая проверка основной функциональности.

**Цель:** убедиться, что программа в принципе работает после изменений.

---

## 2. Оператор `assert`

```python
assert condition
assert condition, "Error message"
```

- `True` → выполнение продолжается  
- `False` → `AssertionError`

Позволяет писать smoke-тесты лаконичнее.

### Плюсы и минусы smoke-тестов на `assert`

| Плюсы                               | Минусы                                 |
|-------------------------------------|----------------------------------------|
| Простота                            | Много ручного кода                     |
| Не нужны библиотеки                 | Сложно масштабировать                  |
| Быстрый запуск                      | Нет нормального отчёта                 |
| Явно показывает ожидаемый результат | Трудно управлять большим числом тестов |

---

## 3. Фреймворки (`unittest`, `pytest` и т.д.)

`assert` умеет только проверять условие.

Фреймворки дают больше:

| Smoke-тест (`assert`)               | Тестовый фреймворк                                                     |
|-------------------------------------|------------------------------------------------------------------------|
| Нельзя проверить исключение         | Можно проверить нужное исключение                                      |
| Нет удобной подготовки данных       | Fixtures, setup/teardown                                               |
| Сложно переиспользовать данные      | Parametrization, fixtures                                              |
| Сложная проверка работы с БД        | Создаёт и очищает тестовую БД                                          |
| Нет автоматического поиска тестов   | Автоматическое обнаружение тестов                                      |
| Плохие сообщения об ошибках         | Подробные сообщения об ошибках и diff<br>(что ожидали, и что получили) |
| Нет изоляции тестов                 | Каждый тест запускается изолированно                                   |
| Нельзя запускать выборочно          | Фильтры, маркеры, выбор конкретных тестов                              |
| Мокинг нужно организовывать вручную | Есть готовые инструменты для мокинга                                   |
